I build **frontend systems** — not just interfaces.

The difference: an interface breaks when requirements change.
A system adapts, scales, and fails gracefully.

After years of shipping production-grade React applications, I've learned that most frontend problems aren't UI problems. They're **architecture problems diagnosed too late.**

My work lives at the intersection of performance engineering, component design, and state systems. I care obsessively about render budgets, data flow predictability, and writing abstractions that the next engineer can actually understand.

> *"Make it work. Make it right. Make it fast. In that order — but never stop at the first."*

## Work

<br/>

**CraftLink** &nbsp;·&nbsp; MERN Stack &nbsp;·&nbsp; [↗](https://github.com/JAI1209)

Full-stack freelance exchange platform. The hard parts weren't the CRUD — they were designing a real-time collaboration layer that didn't degrade under concurrent load, and building an auth system that could handle role complexity without becoming a security liability. Modular API architecture, clean separation between domain logic and HTTP handlers.

`MongoDB` `Express` `React` `Node.js` `WebSockets` `JWT`

<br/>

**SyncDev** &nbsp;·&nbsp; Real-time Collaborative Editor &nbsp;·&nbsp; [↗](https://github.com/JAI1209)

The product: VS Code in the browser, multiplayer. The engineering problem: how do you reconcile concurrent edits from N users without losing data or blocking the UI thread? Built WebSocket room management with graceful reconnection, a dark SaaS interface that feels native, and a render pipeline that stays under 16ms even during heavy input.

`React` `TypeScript` `WebSockets` `Operational Transforms`

<br/>

**Nuve Player** &nbsp;·&nbsp; Media Streaming Frontend &nbsp;·&nbsp; [↗](https://github.com/JAI1209/Nuve)

Streaming interfaces fail in predictable ways: unnecessary re-renders cascade during playback, search queries block the main thread, component trees become impossible to modify. Solved all three. Centralized Redux state with surgical update boundaries, dynamic filter pipeline that stays O(n), modular architecture where any layer can be swapped without touching the others.

`React` `TypeScript` `Redux Toolkit` `Performance Engineering`

<br/>

**LiveFree** &nbsp;·&nbsp; Hostel Booking Platform &nbsp;·&nbsp; **[Live ↗](https://jai1209.github.io/livefree-react/)**

Took an existing static HTML/CSS site and migrated it to a proper React architecture without breaking production. Built a Framer Motion animation system, sticky booking bar with synchronized state, and a photo reorder gallery. The migration story is the interesting part — zero downtime, incremental cutover, preserving SEO.

`React` `Vite` `Framer Motion` `React Router` `GitHub Pages`

## Principles

Things I've learned the hard way, through production bugs and 2AM rollbacks:

- Abstractions that seem clever in isolation become liabilities at scale
- The best component is the one that doesn't exist yet — build only what earns its place
- Performance problems are architecture problems. You can't `useMemo` your way out of bad structure
- State should be as local as possible, as global as necessary
- The test you don't write is the bug you'll debug on Friday evening
- Code is communication. Write it for the engineer who comes after you
